# skills

本目录用于维护 rideclaw 的业务功能技能。每个技能直接放在 `skills/<skill-name>/SKILL.md`，不再按 agent 名称额外嵌套。

## 设计原则

1. 技能只按业务功能划分，不建立通用的 intent、date-time 等横切技能。
2. system prompt 只写身份、边界和通用行为原则；具体怎么执行放在对应技能里。
3. 每个技能都应包含适用范围、能力边界、基础流程、信息要求、输出要求和相关工具。
4. 技能之间可以协作，但一个用户任务应优先由最贴近业务目标的技能承接。
5. 工具字段、调用顺序、异常处理、强约束和关键案例都沉淀在技能文件中。

## 当前技能

### taxi-booking

路径：`skills/taxi-booking/SKILL.md`

负责同城打车、地点验证、价格预估、车型确认和待支付打车订单数据生成。

### hotel-booking

路径：`skills/hotel-booking/SKILL.md`

负责酒店查询、房型筛选、房型确认和待支付酒店订单数据生成。

### transport-booking

路径：`skills/transport-booking/SKILL.md`

负责跨城交通方案搜索、方案确认和待支付交通订单数据生成。

### travel-planning

路径：`skills/travel-planning/SKILL.md`

负责整体行程规划，以及跨城交通、酒店和同城接驳打车的任务拆解。

## 未来技能规划

### flight-booking

负责机票查询、筛选和订单创建。

覆盖范围：
- 单程、往返、多段中的飞机出行段。
- 舱位、航空公司、机场、出发 / 到达时间、价格等偏好。
- 机票订单修改和价格反馈。

建议沉淀：
- 航班搜索字段规则。
- 起飞时间、到达时间和目的地活动时间的处理。
- 航班内部排序规则。
- 机票订单创建字段完整性要求。
- 机票替换关系。

### train-booking

负责高铁、火车、动车查询、筛选和订单创建。

覆盖范围：
- 单程、往返、多段中的铁路出行段。
- 车站、车次、座席、出发 / 到达时间、价格等偏好。
- 火车 / 高铁订单修改和价格反馈。

建议沉淀：
- 车次搜索字段规则。
- 座席偏好和默认选择规则。
- 车次内部排序规则。
- 火车 / 高铁订单创建字段完整性要求。
- 火车 / 高铁替换关系。

### bus-booking

负责巴士、大巴、客车查询、筛选和订单创建。

覆盖范围：
- 单程、往返、多段中的巴士出行段。
- 站点、班次、出发 / 到达时间、价格等偏好。
- 巴士订单修改和价格反馈。

建议沉淀：
- 巴士搜索字段规则。
- 站点距离和同城起终点判断。
- 班次内部排序规则。
- 巴士订单创建字段完整性要求。
- 巴士替换关系。
- 默认时间偏好。
- 班次内部排序规则。
- 订单创建字段完整性要求。
- 修改需求中的替换关系。

### order-modification

负责跨业务的订单修改和价格反馈。

覆盖范围：
- 交通修改。
- 酒店修改。
- 打车修改。
- 整体规划局部修改。
- 价格偏高、换便宜、换时间、换区域、换车型等反馈。

建议沉淀：
- 修改意图识别。
- “确认选择”与“修改需求”的区分。
- 新旧订单或任务的替换关系。
- 多订单替换的处理方式。
- 修改后是否需要重新查询、重新估价或直接下单。

### order-state-summary

负责根据会话日志和工具结果总结当前执行状态。

覆盖范围：
- 已完成步骤。
- 失败步骤。
- 已调用关键工具。
- 是否进入下单、支付、取消、替换环节。
- 酒店、打车、交通等业务状态。

建议沉淀：
- 状态总结格式。
- 只基于日志，不编造。
- 没有记录时明确标注暂无相关执行记录。

### travel-consultation

负责不需要履约的文旅和出行咨询。

覆盖范围：
- 景点介绍。
- 城市怎么玩。
- 路线建议。
- 旅游季节。
- 美食推荐。
- 交通方式对比。
- 签证、行李、机场、车站常识。
- 旅行注意事项。

建议沉淀：
- 直接回答与进入履约的分界。
- 咨询转预订时的上下文承接。
- 不调用工具也能回答的范围。
