# skills

本目录用于维护 rideclaw 的业务功能技能。每个技能直接放在 `skills/<skill-name>/SKILL.md`，不再按 agent 名称额外嵌套。

## 设计原则

1. 技能只按业务功能划分，不建立通用的 intent、date-time 等横切技能。
2. system prompt 只写身份、边界和通用行为原则；具体怎么执行放在对应技能里。
3. 每个技能都应包含适用范围、能力边界、基础流程、信息要求、输出要求和相关工具。
4. 技能之间可以协作，但一个用户任务应优先由最贴近业务目标的技能承接。
5. 工具字段、调用顺序、异常处理、强约束和关键案例都沉淀在技能文件中。

## 当前技能

### taxi-booking

路径：`skills/taxi-booking/SKILL.md`

负责同城打车、预约用车、地点验证、价格预估、车型确认、下单、取消、司机位置查询，以及打车相关的修改和价格反馈。

## 未来技能规划

### transport-booking

负责跨城交通需求的编排和路由，不直接承载所有具体交通工具的履约细节。

覆盖范围：
- 判断跨城交通需求是否完整。
- 单程、往返、多段交通。
- 识别用户指定或适合的交通方式。
- 拆分去程、返程和多段交通任务。
- 将具体履约交给 flight-booking、train-booking 或 bus-booking。
- 交通订单修改和价格反馈。

建议沉淀：
- 搜索前必要信息。
- 往返和多段拆分规则。
- 交通方式选择策略。
- 不同履约技能之间的路由规则。
- 修改需求中的替换关系。

### flight-booking

负责机票查询、筛选和订单创建。

覆盖范围：
- 单程、往返、多段中的飞机出行段。
- 舱位、航空公司、机场、出发 / 到达时间、价格等偏好。
- 机票订单修改和价格反馈。

建议沉淀：
- 航班搜索字段规则。
- 起飞时间、到达时间和目的地活动时间的处理。
- 航班内部排序规则。
- 机票订单创建字段完整性要求。
- 机票替换关系。

### train-booking

负责高铁、火车、动车查询、筛选和订单创建。

覆盖范围：
- 单程、往返、多段中的铁路出行段。
- 车站、车次、座席、出发 / 到达时间、价格等偏好。
- 火车 / 高铁订单修改和价格反馈。

建议沉淀：
- 车次搜索字段规则。
- 座席偏好和默认选择规则。
- 车次内部排序规则。
- 火车 / 高铁订单创建字段完整性要求。
- 火车 / 高铁替换关系。

### bus-booking

负责巴士、大巴、客车查询、筛选和订单创建。

覆盖范围：
- 单程、往返、多段中的巴士出行段。
- 站点、班次、出发 / 到达时间、价格等偏好。
- 巴士订单修改和价格反馈。

建议沉淀：
- 巴士搜索字段规则。
- 站点距离和同城起终点判断。
- 班次内部排序规则。
- 巴士订单创建字段完整性要求。
- 巴士替换关系。
- 默认时间偏好。
- 班次内部排序规则。
- 订单创建字段完整性要求。
- 修改需求中的替换关系。

### hotel-booking

负责酒店查询、房型筛选和订单创建。

覆盖范围：
- 酒店查询、推荐、预订、重选、修改、价格反馈。
- 城市、区域、商圈、景点、会场、办公地点附近。
- 酒店品牌、星级、预算、房型、早餐、可退款等偏好。

建议沉淀：
- 酒店必要信息。
- 入住、离店、晚数规则。
- 酒店检索 destination 规则。
- 工具字段类型要求。
- 酒店和房型筛选规则。
- 未找到结果时的停止条件。

### travel-planning

负责整体行程规划和多业务拆解。

覆盖范围：
- 交通 + 酒店。
- 交通 + 酒店 + 后续送站打车。
- 多城市、多段行程、往返行程。
- 跨城具体地点与城市级目的地的拆解。

建议沉淀：
- 整体规划成立条件。
- 整体规划必要信息。
- 交通、酒店、打车之间的拆分边界。
- 后续交通 / 酒店订单信息触发送站打车的规则。
- 禁止跨城打车的判断边界。

### order-modification

负责跨业务的订单修改和价格反馈。

覆盖范围：
- 交通修改。
- 酒店修改。
- 打车修改。
- 整体规划局部修改。
- 价格偏高、换便宜、换时间、换区域、换车型等反馈。

建议沉淀：
- 修改意图识别。
- “确认选择”与“修改需求”的区分。
- 新旧订单或任务的替换关系。
- 多订单替换的处理方式。
- 修改后是否需要重新查询、重新估价或直接下单。

### order-state-summary

负责根据会话日志和工具结果总结当前执行状态。

覆盖范围：
- 已完成步骤。
- 失败步骤。
- 已调用关键工具。
- 是否进入下单、支付、取消、替换环节。
- 酒店、打车、交通等业务状态。

建议沉淀：
- 状态总结格式。
- 只基于日志，不编造。
- 没有记录时明确标注暂无相关执行记录。

### travel-consultation

负责不需要履约的文旅和出行咨询。

覆盖范围：
- 景点介绍。
- 城市怎么玩。
- 路线建议。
- 旅游季节。
- 美食推荐。
- 交通方式对比。
- 签证、行李、机场、车站常识。
- 旅行注意事项。

建议沉淀：
- 直接回答与进入履约的分界。
- 咨询转预订时的上下文承接。
- 不调用工具也能回答的范围。
